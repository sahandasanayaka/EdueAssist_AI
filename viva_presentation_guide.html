Academic Performance Gap Analyzer & AI Advisory System (MySQL & Google Gemini)

1. How to Start Your Presentation (Your Opening Speech)

When the examiners ask you to introduce the project, speak confidently using this simple, clear pitch:

Speak this in English (Easy to memorise & speak):
"Good morning / Good afternoon, Professors.

Our project is EduAssist AI.

In simple words, this is an academic advisory platform for university students that collects data from the university LMS — including course details, assignment scores, and continuous assessment marks.

A very important point: Students do not submit assignments through this system. Instead, our platform analyzes their existing continuous assessment marks, calculates how much they need to improve (+X% score gap) to reach First Class or Distinction benchmarks, and provides personalized AI revision tips on specific weak topics.

There are only two user roles: Student and Admin, powered by a MySQL database and Google Gemini AI."

Based on your live dashboard screens, here is the exact purpose of every single card and section:

Hero Section & Improvement CTA

Purpose: Sets the purpose of the app immediately. Gives the student two primary action buttons: View Improvement Suggestions (launches AI study roadmaps) and View Coursework Deliverables.

Purpose: Synced directly with LMS database records. Confirms the active curriculum modules the student is currently enrolled in for this semester.

Purpose: Mathematical average of all continuous assessment marks published so far. Shows the student their current standing (Honors Band).

Top Card 3: Improvement Target (+2.5% Gap)

Purpose: Core Feature! Calculates the exact mathematical deficit needed to achieve First Class / Top Distinction (Goal: 95%+). Directly answers "How much do I need to improve?".

Top Card 4: AI Improvement Focus (3 Topics)

Purpose: Identifies the top 3 conceptual areas where marks were lost across coursework, giving immediate focus areas for revision.

Floating AI Copilot (Bottom Right)

Purpose: One-click interactive chatbot. Students can open it anytime to ask specific subject questions or request sample exam problems.

4. How the Files Connect (Step-by-Step Architecture)

Here is the exact technical path from the moment the user opens the page to the MySQL database and AI response:

1

Step 1: Frontend User Interface (React 19 + Vite)

client/src/pages/StudentDashboard.jsx

When the page loads, React runs useEffect() which calls the API function studentApi.getDashboard().

2

Step 2: The HTTP Bridge (Axios & JWT Interceptor)

client/src/services/api.js

Axios sends an HTTP GET request to http://localhost:5000/api/students/dashboard. The request interceptor automatically attaches the user's JWT security token from localStorage into the HTTP Header (Authorization: Bearer <token>).

3

Step 3: Backend Server & Security Routing

server/server.js ➔ server/src/routes/studentRoutes.js

Express server listens on port 5000. It allows requests from port 5173 via CORS. server.js forwards requests matching /api/students to studentRoutes.js, which verifies the JWT token and routes to the controller.

4

Step 4: Database Query Execution (MySQL Pool)

server/src/db/connection.js ➔ server/src/services/studentService.js

Using mysql2/promise, a reusable connection pool executes parameterized SQL queries against eduassist_db. It fetches courses from enrollments and marks from exam_results and assignments tables.

5

Step 5: The AI Brain (Google Gemini Integration)

server/src/services/geminiService.js (@google/genai SDK)

When the student clicks "Get Revision Tips", the backend retrieves the student's real MySQL marks, injects them into a strict Zero-Hallucination Grounding Prompt, and calls the Google Gemini API (gemini-2.5-flash). Gemini returns specific study advice for that exact subject.

6

Step 6: UI Rendering

client/src/pages/StudentDashboard.jsx

The Express controller sends back JSON data. React receives it, updates state via setData(...), and renders the numbers, score gaps, and suggestion cards dynamically.

5. Typical Viva Questions & Ideal Answers (English & Sinhala)

Examiner Question 1:
Q: "Can students submit assignments in this system?"
A: "No, professor. Our platform is not an assignment submission dropbox. It is strictly an academic performance advisory and score gap analyzer. It ingests continuous assessment marks from the LMS to calculate how much students must improve and guides their revision."
💡 සිංහල: "නැහැ සර්, මේක assignment submit කරන එකක් නෙවෙයි. මේක LMS marks analyze කරලා ලකුණු වැඩි කරගන්න උපදෙස් දෙන academic advisory platform එකක්."
Examiner Question 2:
Q: "How does the AI know the student's marks without hallucinating?"
A: "We use a technique called Grounding in geminiService.js. Before contacting the Gemini model, our backend queries the MySQL database for the student's verified coursework marks. We inject this authoritative context into the system prompt with strict zero-hallucination instructions, ensuring the AI only reasons over verified university records."
💡 සිංහල: "අපි Gemini එකට යවන්න කලින් MySQL database එකෙන් ළමයාගේ ඇත්තම marks කියවලා, ඒ දත්ත prompt එකට inject කරලා (Grounding) තමයි AI එකෙන් advice ගන්නේ. ඒ නිසා AI එක බොරු ලකුණු හදන්නේ නැහැ (Zero Hallucination)."
Examiner Question 3:
Q: "What database does this system use?"
A: "We use MySQL exclusively (database name: eduassist_db). We connect asynchronously using mysql2/promise with a connection pool configured in server/src/db/connection.js."
💡 සිංහල: "අපි පාවිච්චි කරන්නේ MySQL පමණයි (`eduassist_db`). `mysql2/promise` pool එකක් හරහා තමයි backend එක connect වෙන්නේ."
Examiner Question 4:
Q: "What are the roles in this system?"
A: "There are only two active roles: Student (who views personalized score gaps, revision suggestions, and study roadmaps) and Admin (who manages student records, courses, and system analytics)."
💡 සිංහල: "system එකේ roles 2ක් පමණයි තියෙන්නේ — Student සහ Admin."
